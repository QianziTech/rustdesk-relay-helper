# 实施规划

当前进度（2026-09-28）：第一版核心、CLI、Bash 入口、systemd 模板和本地测试已实现，使用方式见 [README](../README.md)。阶段 0 的真实环境输入及阶段 3 的现场验收尚未完成；仓库实现不表示已部署或完成生产验证。

2026-09-30：个人自用的本机 token WebUI 另在 `feature/local-token-webui` 分支试验，新增范围、接口及验证见 [WebUI 方案](WebUI方案.md)。下文的 Web 暂缓描述保留为第一版原始规划。

本计划对应[方案与技术选型](./方案与技术选型.md)。第一版目标是管理现有 OSS `hbbs` 下发的**一个** relay，完成按层级与 RTT 排名的自动选择、纯优先级容灾节点、故障切换和 Bash 命令操作。RTT 排名属于第一版范围，不留待后续版本。

## 阶段 0：确认现场接口

只读检查 `docker inspect hbbs` 的镜像版本、启动参数与网络模式；读取 `rs` 当前值；确认节点地址、目标机 Python 版本和 CNHZ 本地 `hbbr` 是否可用。记录真实客户端 Relay Server 是否为空。此阶段不对生产 `hbbs` 写命令。

完成条件：拿到实际 `rs` 输出和可用于验收的三个真实节点（备用可暂缺，策略仍按配置中现有节点运行）。若 `rs` 读不到可靠结果，先解决接口问题，再进入下一阶段。

## 阶段 1：最小可运行版本与 RTT 选择策略

实现向 `127.0.0.1:21115` 发送单条命令的读写函数、超时处理与 `rs` 列表解析。适配器只接受配置文件中已定义的单个 relay 地址，禁止把逗号列表当作自动策略输出。写入后用独立连接重读；因更新是异步的，允许短时间轮询，最终以回读结果为准。

实现 INI 配置加载、TCP connect 探测、连续计数、按 `tier` 选择、同层 RTT 排名、纯优先级节点顺序兜底、故障切换、恢复回切和全部不可用时保留现状。`rtt_ranked` 默认开启；关闭后节点仍参与健康探测和自动故障切换，但不进入 RTT 排名。JSON 仅保存跨周期必需的状态，包括用于排名的有限近期 RTT 样本；探测结果与成功切换事件输出到 journal。每次运行先取文件锁，再读配置、状态和 `hbbs` 实际值，最后决定是否写入。

本地用可控 TCP 假服务验证 `hbbs` 的“空响应、延迟生效、超时、错误列表”，并用确定性的探测结果序列测试：短时失败不切换、三次失败切备用、不同 `tier` 间不因 RTT 越级、同层按近期 RTT 中位数选择、新节点首点参与 RTT 排名、两分钟过期退出排名、五点滑动淘汰、RTT 改善不足阈值时不切换、保持期内不因 RTT 抖动切换、`rtt_ranked = false` 的节点在其顺序到达时能够自动兜底、同层 RTT 节点恢复后按阈值和保持期从纯优先级节点回切、主节点恢复六次且保持期到后切回、全部失败保留实际值、重启后手动模式保持、`hbbs` 重启导致的运行时值丢失能够被重新应用。`minimum_hold_seconds` 只约束健康节点间的主动切换和恢复抢回，不延迟故障逃离。现场首次写操作使用一个已经通过真实客户端验证的地址，再确认新建中继会话是否走该节点；成功后才启用自动执行。

## 阶段 2：Bash 命令与定时任务

增加 `status`、`nodes`、`probe`、`switch`、`auto`、`history` 的 Bash 入口，并配置 `systemd` oneshot service 与约 20 秒的 timer。`status` 和 `nodes` 显示节点层级、RTT 排名开关、原始探测耗时、有效 RTT 及本次选择原因。`probe` 只更新探测结果；`switch` 和 `auto` 才改变模式并按规则触发写入。管理员与定时任务共用锁，忙时给出可理解的提示。

检查目标机权限与文件位置：配置由管理员编辑，运行进程需能写入状态目录；默认 systemd 部署使用 root，无需专用账户。宿主机进程须能访问 loopback 的 `21115`。不挂载 Docker socket，也不在第一版开放网络管理端口。

## 阶段 3：现场验收

按现场配置的节点层级逐一确认端口连通及真实的两端中继会话。再做受控故障、恢复和同层延迟差异演练，核对 `status`、有效 RTT、选择原因、`rs` 回读、切换时间与真实新会话的 relay；同时验证纯优先级容灾节点不会因低 RTT 抢占排名节点，但会在其优先顺序到达时接管。最后验证 `hbbs` 容器重启后管理器能恢复期望地址，以及手动模式不会被定时任务覆盖。

若只有 TCP 探测正常但真实会话失败，停止该节点的自动使用并排查网络、密钥和客户端配置；不能把 TCP 成功直接作为端到端验收。

## 暂缓事项

Web 界面、远端探针、`hbbs` 自身高可用、节点自动发现、数据库与 Docker 容器重建都不属于第一版。它们需要独立的功能依据和验收方式。第一版 RTT 仅使用 CNHZ 管理器到 relay 的 TCP 建连耗时进行同层排名，不扩展为多地客户端视角或跨层加权评分。
