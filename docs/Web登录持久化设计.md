# Web 登录持久化设计

状态：2026-10-02 已实现并完成本地 HTTP 与 Chromium 回归；真实 SSH 隧道及生产部署尚未验收。

实施基线：拉取后的 `origin/master`，提交 `94a7e3ae1ecc6a29ddb1fb771332dc0fe863c5ec`（合并本机 token WebUI）。设计阶段的 `docs/web-login-session-design` 在当前工作区恢复并改名为 `feature/web-login-persistence`。基线已有 WebUI、配置 GUI 与 INI 双向编辑；本文在 [WebUI 方案](./WebUI方案.md) 上扩展登录持久化，继续遵守 [方案与技术选型](./方案与技术选型.md) 的 relay 策略及共享操作合同。远端基线已核对，不代表已读取或验收线上进程。

本次实现登录、会话查询、退出和配置草稿保留，恢复此前的开发规范并同步文档。未操作生产服务、真实 token 文件或 systemd 配置。

## 1. 背景与决策

实施前，页面从 URL 读取访问 token 后立即清理地址，只在页面变量中保留 token。刷新时浏览器先发送裸入口请求，原 `Handler.authorized(entry=True)` 在页面脚本执行前返回 401。仅改用 `sessionStorage` 无法解决这个问题：浏览器不会自动把 Web Storage 的内容附加到页面导航请求中。

以下记录 `94a7e3a` 基线上的历史行为；实施后的接口见第 4 节：

| 位置 | 实施前行为 |
| --- | --- |
| `relay_helper/web.py` 的 `load_token` | 首次生成 256 位随机 token，原子创建权限 `0600` 的文件；校验属主与非符号链接，普通重启沿用文件内容 |
| `LocalServer` | 单进程 `ThreadingHTTPServer`，固定监听 IPv4 `127.0.0.1`，默认端口 `8765`，无更改监听地址的选项 |
| `Handler.authorized` | 入口接受唯一正确的 URL token，裸入口及错误 token 返回 401；全部 API 使用 Bearer，不接受 API 查询参数 |
| 来源检查 | Host 只接受 `127.0.0.1:<端口>` 或 `localhost:<端口>`；存在 Origin 时须与 `http://<Host>` 一致；Fetch Metadata 只接受缺失、`none` 或 `same-origin`，无 CORS 放行 |
| `relay_helper/webui.html` | 从 URL 获取 token，立即 `history.replaceState`；业务请求携带 Bearer；初始化读取一次状态，后续由用户操作刷新，无自动轮询 |
| 响应与日志 | `no-store`、`no-referrer`、禁止 iframe、随机 nonce CSP、无外部资源；不记录请求 URL，仅交互终端输出完整 token 地址 |
| `tests/test_web.py` | 已有原始 token 跨重启、裸入口拒绝、来源检查及未认证请求不调用后端等测试 |

采用以下方案：

- 首次凭访问 token 登录后，换取服务端生成的随机会话 ID，通过 `HttpOnly` Cookie 携带。
- 页面入口和受保护接口使用同一套会话校验，正常刷新无需重新输入访问 token。
- 默认使用会话 Cookie；“记住登录”默认不勾选，勾选后最长保留 7 天，并由服务端强制过期。
- 会话只保存在 Web 服务进程内存中，不写入磁盘，不引入数据库或共享会话存储。
- Web 服务进程重启后全部会话失效，包括“记住登录”的会话；浏览器残留 Cookie 不能恢复登录。
- 访问仅通过 SSH 隧道提供，保留来源检查、CSRF 防护和 XSS 防护。

本设计将“服务重启后 token 失效”落实为**浏览器持有的 Web 会话凭据失效**。首次登录使用的原始 `webui.token` 保持当前跨重启保存的行为；不额外规定每次重启时轮换它，也不改变 `test_generated_token_is_private_and_survives_restart` 合同。服务重启后，管理员必须显式重新提交当时有效的访问 token，建立新会话，前端不保留原始 token 以自动恢复会话。

## 2. SSH 隧道与安全边界

沿用当前固定 IPv4 回环监听，不新增监听地址选项。本方案的部署前提是：远端 Web 服务只监听 `127.0.0.1`，SSH 本地转发端口也只绑定 `127.0.0.1`，浏览器通过本机回环地址访问。不得把远端 Web 端口直接暴露到公网或局域网，也不得将本地转发端口绑定到所有网卡。

保留当前更换 SSH 本地端口的能力：浏览器可访问 `127.0.0.1:<本地端口>` 或 `localhost:<本地端口>`，本地端口无需与远端默认的 `8765` 相同。会话绑定经校验的浏览器来源；更换主机名或本地端口后需重新登录，不要求新增服务器端来源配置。

SSH 隧道保护本机与远端之间的传输，本机浏览器到本地转发端口、远端 SSH 服务到 Web 服务之间为回环通信。在这些前提成立时，可以使用回环 HTTP，无需为登录持久化额外部署 HTTPS。SSH 主机身份验证仍应正常启用。

SSH 认证并不证明每个 Web 请求都由管理员主动发起。用户在打开隧道时访问的其他网站可能尝试请求本机端口，本机其他进程也可能访问转发入口，因此 Web 会话与来源校验仍有必要。

关闭隧道只会使入口暂时不可达，不撤销会话。隧道恢复后，若 Web 服务没有重启且会话未过期，浏览器可以继续使用该会话。

本设计不防御已被攻陷的管理员设备、恶意浏览器扩展或具备足够权限的本机进程。若未来允许非回环访问，应重新评估部署边界并启用 HTTPS，不能直接沿用回环 HTTP 配置。

## 3. 凭据与会话数据

| 数据 | 用途 | 保存位置与生命周期 |
| --- | --- | --- |
| 原始访问 token | 首次登录时证明访问权限 | 沿用既有管理方式；浏览器不将其写入 `localStorage`、`sessionStorage` 或持久 Cookie |
| 随机会话 ID | 后续页面导航和接口请求的认证凭据 | 仅通过 HttpOnly Cookie 交给浏览器；退出、到期、撤销或 Web 服务重启后失效 |
| 服务端会话记录 | 判断会话是否存在、权限是否有效、是否到期 | 仅保存在单个 Web 服务进程内存中 |
| CSRF token | 防止非预期来源伪造写操作 | 与会话绑定，可由同源页面读取；它不是登录凭据，不替代会话校验 |

会话 ID 与 CSRF token 各使用 32 字节密码学安全随机值。会话 ID 不包含原始访问 token，不由访问 token、时间戳或客户端提交值直接派生。每次登录成功生成新 ID，不把未认证会话直接升级为已认证会话。

服务端记录包含会话 ID 的摘要、创建时间、固定过期时间、记住登录标记、绑定来源与 CSRF 校验信息。当前只有共享管理员权限，不新增账号或角色，也不新增动态凭据版本校验、每请求读取 token 文件的机制。接口不得返回原始访问 token 或会话 ID，日志不得记录访问 token、Cookie 值或 CSRF token。

会话表属于单个 `LocalServer`，使用独立线程锁保护查询、创建、撤销和清理，因为 `ThreadingHTTPServer` 的请求会并发执行。只在访问会话表时持锁，不在持锁期间调用 `Backend.run`、联系 hbbs 或保存配置。业务操作继续使用现有 `<state>.lock`；会话不写入状态 JSON、token 文件或配置备份。退出撤销后的新请求必须拒绝，不承诺中途取消已经通过鉴权并开始执行的操作。

当前上限为 128 个有效会话；新登录先清理过期记录，容量满时返回 429，不驱逐其他浏览器。带当前同源有效 Cookie 的重新登录撤销旧会话后替换为新会话。失败登录限速为全实例 60 秒内 5 次失败，达到上限后登录交换返回 429，等待失败时间窗口恢复；成功登录清除失败计数。不按可变的本地转发端口拆分限速。

会话 ID 本身仍是可重放的凭据。HttpOnly 减少页面脚本直接读取和外带它的机会，不使会话变成不可窃取或不可滥用的凭据。

## 4. 登录、刷新与退出流程

### 4.1 首次登录

1. `Handler.do_GET` 分流：裸入口无有效会话时返回独立的 `login.html`，不返回管理页面、配置或状态；有有效会话时返回 `webui.html`。未新增代理。
2. 管理员显式提交访问 token 和“记住登录”选择。登录使用 POST、唯一 Bearer 头与 JSON 请求体，校验来源并限制请求格式，不通过 GET 执行登录。打开原有含 token 的书签只返回登录确认页，不自动创建会话，也不默认记住登录。
3. 服务端验证访问 token，限制失败尝试频率；未通过时不创建已认证会话。
4. 验证成功后生成新会话 ID 和 CSRF token，保存内存会话记录，设置 Cookie。
5. 前端清除输入框和临时变量中的原始访问 token，后续请求依赖 Cookie，不继续发送原始 token。

已实现的接口合同如下。业务路径、请求体与后端操作保持不变，认证方式由 Bearer 迁移为会话。

| 请求 | 行为 |
| --- | --- |
| `GET /` | 有有效会话返回管理页面，否则仅返回登录页 |
| `GET /?token=...` | 校验唯一正确的原始 token 后返回登录确认页，不执行业务或创建会话；错误、空值、重复 token 和额外参数继续拒绝 |
| `POST /api/session/login` | 唯一 Bearer 头提交原始 token，JSON 为 `{"remember":false}` 或 `{"remember":true}`；成功创建会话、设置 Cookie，并返回与会话查询相同的公开信息 |
| `GET /api/session` | 有有效会话时返回 `authenticated`、`created_at`、`expires_at`、`remember` 与 `csrf`，不返回原始 token 或会话 ID |
| `POST /api/session/logout` | 验证会话、来源及 CSRF，撤销会话并清除 Cookie |
| 现有管理 `/api/*` | 仅凭会话认证，JSON POST 另须与会话绑定的 CSRF token；保留禁止查询参数、业务校验和锁语义 |

兼容登录页从当前 URL 临时读取 token 后立即沿用 `history.replaceState` 清理地址，管理员确认后才发起登录 POST。若清理后尚未登录就刷新，需要重新输入 token 或打开原书签，不为该过渡流程使用 Web Storage。裸入口也支持手动输入 token。登录成功后清除输入及临时变量，通过不含 token 的入口重新载入管理页面；管理页面不再从 URL 取 token 或构造业务 Bearer 头。

原始 Bearer 仅用于登录交换，管理 API 不保留 Bearer 回退通道，避免绕过会话期限。登录页保留 no-referrer、无外部资源和不记录 URL 的行为；清理地址无法消除首次请求可能留下的浏览器历史、扩展记录或终端录制。

裸入口返回登录页是对基线“裸入口 401 且不返回任何页面”合同的明确变更；未认证用户仍不能获取管理页面、配置或状态。测试已调整入口及业务 Bearer 合同，并新增会话生命周期和安全回归。

### 4.2 刷新与接口请求

页面导航和受保护接口均检查 Cookie 对应的会话是否存在、是否过期及是否匹配绑定来源。所有管理数据和写操作都在服务端鉴权，不能只依靠前端“已登录”状态。

站内刷新时，浏览器自动携带符合 Cookie 策略的会话 ID，服务端在返回页面之前识别会话。前端可通过同源会话状态查询获取必要的授权状态与 CSRF token，不获取会话 ID 或原始访问 token。

Cookie 缺失、未知、过期或已撤销时，页面导航返回登录页，受保护接口返回 401，不执行操作。前端显示“登录已失效，请重新登录”，保留未保存的配置草稿供用户处理，不自动重试探测、切换或保存，不自动重新建立会话。本次不新增轮询。会话不存在时不必判断它是由于重启、过期还是撤销而失效。

草稿仅在当前页面内存与 DOM 中保留。失效后可在当前页面输入 token 重新登录，取得新 CSRF 后恢复操作按钮；重新登录本身不重新读取配置或重放业务请求。刷新、关闭页面或确认主动退出仍会丢失未保存草稿，不将草稿持久化到 Web Storage。

来源拒绝继续为 403，锁或配置版本冲突继续为 409，hbbs 未确认继续为 502；保留已有共享操作与配置 GUI / INI 行为，不将所有错误统一显示为登录失效。

### 4.3 退出与凭据轮换

退出登录属于写操作，需要来源与 CSRF 校验。服务端撤销当前会话，并以匹配的 Cookie 名称、主机作用域和路径清除浏览器 Cookie。仅删除浏览器 Cookie 不算完成退出；复制的旧会话 ID 也必须不能再访问接口。

沿用当前原始 token 轮换方式：先停止 Web 服务，删除或按原有权限约束替换 token 文件，再启动。停止时全部内存会话失效，重启后旧 token 不能换取新会话。普通重启不删除文件 token，但同样丢弃全部会话。运行中直接修改或删除文件不会改变当前内存 token，也不会立即撤销会话；本方案不新增热轮换，不能声称文件修改即时生效。保持 token 的原子创建、0600、属主、非符号链接和保留路径检查。

同一浏览器不同标签页通常共用 Cookie；退出其中一个标签页后，其他标签页的后续请求也应失效。不同浏览器的独立会话不因单次退出而全部撤销，但服务重启和原始访问 token 撤销应使相关会话全部失效。

## 5. Cookie 策略

| 属性 | 决策 |
| --- | --- |
| 值 | 随机会话 ID，不保存原始访问 token |
| `HttpOnly` | 必须设置 |
| `SameSite` | 显式设置 `Strict` |
| `Domain` | 不设置，使用 host-only Cookie |
| `Path` | 使用 `/`，覆盖登录入口、管理页面和接口 |
| `Secure` | 当前 SSH 回环 HTTP 不设置；未来扩展 HTTPS 时必须设置 |
| 普通登录的 `Max-Age` / `Expires` | 不设置，采用会话 Cookie |
| 记住登录的保存期限 | 设置最长 7 天的 `Max-Age`，实际授权期限仍由服务端决定 |

当前 SSH 回环 HTTP 模式不设置 `Secure` 或使用 `__Host-` 前缀，避免把 localhost 的浏览器例外作为未经验证的兼容性前提。保留 HttpOnly、Strict 和 host-only 限制；该选择只能用于上述 SSH 隧道边界，不能推广到非回环 HTTP。本次沿用 IPv4 监听，不扩展 IPv6。

HTTPS 是未来独立范围，届时设置 `Secure` 并优先使用 `__Host-` 前缀，不信任任意代理头自动降级。本次不新增 HTTPS 配置或代理支持。

`SameSite=Strict` 允许正常站内刷新，但外站链接进入时首个请求可能不携带 Cookie。现有 Fetch Metadata 检查本身也拒绝跨站导航，不为了外站链接体验放宽它；通过直接输入地址或书签访问本地入口。不能把 Cookie 未发送误当作需要撤销会话，也不能通过携带 token 的重定向绕过来源防护。

Cookie 不按端口隔离，`SameSite` 也不等于同源。应尽量固定访问主机名，并避免在同一主机名上运行不可信的 HTTP 服务。不同实例使用不同 Cookie 名称，减少覆盖冲突，但这不提供端口之间的安全隔离。使用不同主机名时，浏览器不会自动共享原有 host-only Cookie。

Cookie 名称为 `relay_helper_session_<摘要前缀>`，摘要由当前原始 token 与服务监听端口生成，普通重启保持相同名称；不同 token 或监听端口区分实例。名称不含原始凭据，Cookie 值仍为独立随机会话 ID。

会话绑定经校验的浏览器来源，防止本应用在另一转发端口误接受残留 Cookie；此绑定不能防止同主机名的其他 HTTP 服务收到 Cookie。拒绝重复的目标会话 Cookie，避免不同路径残留产生歧义。来源不匹配时拒绝请求，不无条件删除仍可能供原入口使用的会话记录。

## 6. 有效期与服务重启

| 模式 | 浏览器保存策略 | 服务端有效期 | Web 服务重启后的结果 |
| --- | --- | --- | --- |
| 普通登录 | 会话 Cookie | 从登录时刻起最长 8 小时 | 立即失效，重新凭访问 token 登录 |
| 记住登录 | 最长 7 天的持久 Cookie | 从登录时刻起最长 7 天 | 同样立即失效，不自动恢复 |

普通登录的 8 小时与记住登录的 7 天通过 `web.py` 中的 `SESSION_SECONDS`、`REMEMBER_SECONDS` 固定，不新增 CLI 或 INI 参数。浏览器保存期限不能延长服务端授权期限。两种模式都使用固定绝对期限，访问、刷新、轮询和隧道重连不延长期限；仅登录与退出响应设置 Cookie，不在普通请求中重发或续期。

最小方案不额外加入空闲超时，避免管理页面自动轮询影响判定，也避免短空闲期限抵消“记住登录”的作用。若后续需要空闲超时，应单独明确真实用户活动的定义、普通与记住登录的差异；后台轮询不能默认计入用户活动。

进程内会话期限使用单调时钟判断，避免运行期间系统时间调整延长授权。请求校验和新登录时清理过期记录，限制会话总量，防止内存无限增长。接口的 Unix 时间戳仅用于显示，不参与授权期限计算。

Web 服务启动时会话表为空，不从文件、业务状态、浏览器 Cookie 或客户端提交内容恢复会话。禁止把可独立验证且跨重启继续有效的签名 Cookie/JWT 当作本方案的会话替代品。旧 Cookie 即使尚未达到浏览器保存期限，也必须被新进程拒绝。

这里的重启特指持有会话表的 Web 服务进程重启；`hbbs`、定时任务或其他独立进程重启不应被自动视为 Web 会话重启。实现采用单个会话所属进程；不支持每个工作进程各自维护不同会话表的多进程、多实例部署。将来增加并行部署时，需要重新设计统一会话状态和全量失效语义。

现有 `rustdesk-relay-helper-web.service` 的 `Restart=on-failure` 也会创建新 Web 进程，所以崩溃后的自动重启同样使旧会话失效。无需修改 systemd 服务，原始 token 文件继续沿用。

浏览器可能恢复会话 Cookie，因此关闭浏览器不保证退出。关闭 SSH 隧道也不保证退出。可保证的失效条件是主动退出、固定期限到达、访问凭据撤销或轮换、Web 服务进程重启。

“记住登录”文案应明确为“最多 7 天；服务重启后需重新登录”，不能承诺一定保持 7 天。

## 7. 来源、CSRF 与 XSS 防护

- 拆分并复用 `Handler.authorized` 中的本机 Host、来源及路径检查，使其先于登录或会话认证。Host 仍限于既有 `127.0.0.1` 与 localhost 形式并检查合法端口，拒绝重复 Host；不接受任意主机，也不信任代理头扩展范围。
- 保留当前按经校验 Host 精确比较 `http://<Host>` 的来源规则，以及不同 SSH 本地端口的访问能力，不新增来源允许列表配置。已登录请求同时与会话绑定来源比较，协议、主机和端口必须一致。
- 登录、退出及所有 JSON POST 要求单一合法的同源 Origin；拒绝缺失、重复、`null` 或跨源值。相较基线仅在 Origin 存在时校验，写接口已增强。普通 GET 导航可能没有 Origin，允许合法刷新。
- 登录仅接受唯一原始 Bearer 头和指定 JSON；业务 POST 另要求与会话绑定的 CSRF 自定义头。拒绝简单表单和跨域凭据授权，继续无 CORS 放行；GET 不执行业务写操作。
- Fetch Metadata 继续只接受缺失、`none` 或 `same-origin`，不放宽为 `same-site`。SameSite 与 Fetch Metadata 都不能替代会话认证、精确来源及 CSRF 校验。
- 保留单一 Content-Length、拒绝 Transfer-Encoding、application/json、64 KiB 上限和业务请求体校验。认证失败不调用 `Backend`，不触发 hbbs 或磁盘操作。
- 保留 nonce CSP、`no-store`、`no-referrer`、禁止 iframe、无外部资源和不记录 URL。当前 CSP 的 `form-action 'none'` 要求登录通过受 nonce 保护的脚本提交 JSON，不为普通表单扩大策略。
- 保留输出转义、安全 DOM 操作及既有 XSS 防护，不把不可信配置或错误信息插入可执行 HTML；日志不记录 Bearer、Cookie、CSRF 或敏感请求体。

HttpOnly 保护 Cookie 的脚本读取能力，但 XSS 仍可能在当前页面内读取 CSRF token、携带 Cookie 调用接口和执行管理操作。SSH 隧道与 Cookie 方案均不能替代 XSS 修复。

## 8. 验收场景

实现位于 `relay_helper/web.py`、`relay_helper/login.html`、`relay_helper/webui.html` 和相应测试；未复制 `service.py` 策略，CLI、timer 与共享锁沿用原合同。README 和 WebUI 方案已同步入口、Bearer、刷新与退出说明。

以下为验收合同。本地自动化覆盖认证、来源、固定过期、并发、重启与草稿保留；真实 SSH 隧道、浏览器恢复、部署机权限与生产服务仍需现场验证。

| 场景 | 预期结果 |
| --- | --- |
| 未登录访问裸入口 | 显示可用登录页，不泄露管理数据 |
| 有效 token 首次登录后刷新、直接访问站内页面 | 无需重新输入 token，入口与接口均接受有效会话 |
| 无效、重复 URL token，伪造或随机会话 ID | 拒绝认证，不创建授权会话，不调用后端 |
| 兼容含 token 书签 | 显式确认前不创建会话，默认不记住；地址及时清理 |
| 原始 token 文件普通重启、原子创建与权限校验 | 保留现有文件生命周期和对应测试 |
| 普通会话达到服务端绝对期限 | 即使浏览器仍发送 Cookie，也拒绝访问 |
| 记住登录到达第 7 天、持续轮询或反复刷新 | 不续期，服务端拒绝过期会话 |
| 普通登录或记住登录后重启 Web 服务 | 两种会话全部失效；旧 Cookie 无法访问，必须重新登录 |
| 重启后重新提交有效访问 token | 生成新会话，不恢复旧 ID；重放旧 ID 仍被拒绝 |
| 仅断开并重连 SSH 隧道 | 未过期且未撤销的会话仍可使用 |
| 关闭并恢复浏览器 | 不假定 Cookie 已清除，仍以服务端状态和期限为准 |
| 主动退出后重放旧 Cookie、另一标签页请求 | 均被拒绝；不同浏览器的独立会话按设计保留 |
| 停止、删除原始 token 文件、再启动 | 旧 token 和旧会话均失效，新 token 可建立新会话 |
| 更换 SSH 本地端口或主机名 | 需重新登录，不能误用绑定到原入口的残留会话 |
| 来自恶意外站、同站不同源、缺失或重复 Origin、错误 CSRF 的 POST | 拒绝执行；正常无 Origin 的页面 GET 仍可使用 |
| 从外站链接进入 Strict Cookie 页面 | 保留既有跨站来源拒绝；不因此撤销已有会话 |
| 重复 Cookie、会话容量上限、并发登录与退出 | 可预测地处理，无会话表竞态，不绕过请求约束 |
| 锁冲突、配置版本冲突、hbbs 未确认 | 保留 409 / 502，不错误地报告为登录失效 |
| 目标浏览器和实际回环地址 | 验证 Cookie 设置、刷新、过期、清除及 CSP，不假定 HTTP Secure 例外 |
| 检查本地与远端监听地址 | 均仅绑定回环，公网和局域网不可直接访问 Web 入口 |
| 检查浏览器存储、接口与日志 | 不持久保存或返回原始访问 token，不记录敏感凭据 |

本地验证：`python -m unittest discover -s tests -v` 的 82 项测试通过，保留原始 token 生命周期与业务测试，新增会话、来源和并发回归。`python tests/browser_login.py` 的 2 项 Chromium 测试通过，使用临时配置、模拟 hbbs 和真实本地 HTTP 服务，覆盖首次确认、刷新、跨标签页退出、记住登录、重启失效，以及 GUI / INI 草稿保留、重新登录不重放请求和再次确认保存。该脚本需开发环境有 Playwright 与 Chromium，否则明确跳过；生产仍只用 Python 标准库。真实 RustDesk 中继会话、SSH 隧道、部署权限和 systemd 运行继续按已有现场验收边界处理。
