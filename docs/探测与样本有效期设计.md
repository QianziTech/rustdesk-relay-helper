# 双次探测、样本有效期与手动切换

## 目标与依据

本分支基于 `origin/master` 的 `bf41c384a0955743f1cc564d95d6af364d3f20dc`。本设计更新第一版策略合同中“初始恢复”和“满样本排名”的约束；静态层级、故障阈值、故障恢复、保持期、手动模式持久化和写后独立回读继续保留。

定时任务是单次进程，WebUI 是常驻进程。原实现把解析和 TCP 建连耗时共同计入一次 RTT；首次请求偏高的现场原因尚未确认。参考 [Mihomo 的统一延迟实现](https://github.com/MetaCubeX/mihomo/blob/88dcbf7f1614a67c3b36b848ee3592dfa92ada36/adapter/adapter.go#L251-L277)，采用先测一次、再测一次的方式。Mihomo 可复用 HTTP 连接，本工具仍建立两条独立 TCP 连接；不保证等同 ICMP ping。

本文 RTT 表示延迟，TTL 表示探测点有效期，均不采集 IP 包的 TTL 字段。不增加 HTTP 探测、依赖或部署自动化。

## 一轮探测

- 每个节点顺序建立两次独立 TCP 连接，不同节点仍最多 16 个并行；每次沿用连接超时。单轮网络开销约为原来的两倍，不循环测五次。
- 两次都成功时，用第二次 RTT 生成一个成功探测点；不取最小值，以保留第二次真实变慢的信号。
- 任意一次失败（含超时）时，整轮失败，不加入 RTT 点。两次结果及错误都保存在最近探测详情中，便于区分首请求高值和间歇故障。
- 每轮只更新一次成功/失败计数，不把两条连接计成两轮恢复。
- 当前标准库 `socket.create_connection` 的超时约束每次地址连接，DNS 和多个候选 IP 仍可能延长总耗时；本次不声称提供包含 DNS 的整轮硬超时。

## 有效样本与健康

- 每个成功点保存完成时的 UNIX 时间和 RTT。`rtt_sample_count` 为窗口上限，范围 1–5，默认 5；超过上限时丢弃最早的点。
- 点年龄必须满足 `0 <= 年龄 < 120 秒`。等于两分钟、未来时间点均不可用于健康或排名。读取状态、展示及决策时都检查有效期，不因读取而续期。
- 有 1–4 个点时使用全部有效点的中位数，满五点后使用滑动窗口，不再等待满窗口。
- 新增、改地址或过期后未知的节点，一轮完整成功即可判健康；从未成功的节点保持未知。连续失败达到 `fail_after`（默认 3）才判故障，并清空 RTT 点。
- 已判故障节点仍须连续 `recover_after` 轮完整成功（默认 6）恢复，期间不参与排名。失败中断恢复计数；超过两分钟的探测间隔中断连续计数。即使 RTT 窗口最多五点，恢复计数仍可累计到六。
- 少于故障阈值的短暂失败沿用原来的容错：仍健康且存在有效成功点时可保留当前节点，排名使用有效历史点；最近 RTT 和最近错误明确展示本轮失败。达到故障阈值后不能使用历史低值。
- 没有有效成功点时，原健康节点变为未知；故障节点保持故障，避免通过过期绕过恢复要求。未知节点不能成为候选，实际 relay 不被清空；手动意图仍保留。
- 系统时间回拨使未来样本无效，清除相关连续计数。旧版纯数字样本无法确定逐点时间，升级时废弃，保留手动意图与已确认 relay；故障节点继续执行恢复条件。格式损坏及非有限数值拒绝加载。

## 操作边界

`probe`、`auto`、`reconcile` 探测所有启用节点。`switch <id>` 先校验目标存在且启用，然后只对目标执行双次探测；其他节点的计数和样本不因切换而更新。所有操作继续共用状态锁。

手动切换仍需本轮完整成功且目标健康；初始节点本轮成功即可，故障恢复中的目标仍需达到恢复阈值。本轮失败时拒绝切换，即使历史健康状态尚未达到故障阈值；定时任务处于手动模式时也不重新应用本轮失败的目标，只提示并保留意图。写入前读取 hbbs 实际值，写入后独立连接回读；确认失败保留手动意图，不更新成功切换时间。无候选或控制台异常均不得清空实际列表。

## 验证与上线边界

覆盖双次成功与四种成功/失败组合、第二次慢值保留、目标独占探测、无效目标零网络调用、新节点首点排名、五点淘汰、两分钟边界、失败与恢复序列、故障逃离与保持期、状态升级和损坏、WebUI/CLI 过期展示、TCP 假服务确认流程。运行全部 unittest、Bash 与 systemd 配置检查。

真实配置不覆盖，状态不提交；常驻 Web 服务升级后需重启。真实 DNS、TCP 路径、systemd 常驻运行及客户端中继会话仍需现场验证。本任务只提交分支和草稿 PR，不操作 master 或生产服务。
